# План переезда с Flutter на Kotlin Multiplatform

Как переписать текущее Flutter-приложение на архитектуру из [architecture.md](architecture.md). План покрывает **только переписывание**: в конце мы получаем то же приложение для десктопа на новом стеке. Как развивать его дальше (сервер, синк, мобильные платформы) — не здесь.

Статус: черновик, октябрь 2026.

---

## Рамки

**Делаем:**

- модули `core`, `client`, `app`, только для десктопа;
- собираем и проверяем только на Windows;
- паритет функций с Flutter-версией плюс исправление известных багов;
- установщик `.msi`;
- удаление Flutter в конце.

**Не делаем:** сервер, синхронизацию, Android, iOS, веб, новые функции, заготовки и пустые папки «на будущее».

**Технологии:**

| Что | Выбор |
|---|---|
| Сборка | Gradle (Kotlin DSL), версии в `gradle/libs.versions.toml` |
| JDK | 25 (LTS). Совместимость проверяем на этапе 1 |
| Язык и UI | Kotlin, Compose Multiplatform — последние стабильные версии |
| Модули | `core`, `client`, `app`, пакет `com.polylingy` |
| Тесты | `kotlin.test` |
| БД | SQLite через SQLDelight |
| JSON | kotlinx.serialization |
| Время | kotlinx-datetime |
| Состояние UI | официальные ViewModel и Navigation для Compose Multiplatform |
| DI | вручную, класс `AppContainer` |
| id | UUID везде |

## Правила работы

- **Один этап — одна ветка**, например `feat/kmp-core`. Этап заканчивается проверяемым результатом: тесты или запуск.
- **Flutter-код не трогаем** до последнего этапа. Он остаётся работающим эталоном для сверки поведения; баги в нём не чиним.
- **Оба проекта живут рядом.** `flutter run` и `./gradlew` работают независимо, имена Gradle-модулей не пересекаются с папками Flutter.
- **`CLAUDE.md` и `README.md` обновляем один раз**, на последнем этапе. До этого они описывают Flutter-версию, а новая часть описана в `docs/`.
- **Старый прогресс не переносим.** Новая версия начинает с пустого журнала.
- **Новое приложение хранит данные отдельно от Flutter-версии**: один файл БД `Documents/polylingy/polylingy.db`. Файлы Flutter (`progress.db`, `courses/`) не трогаем.

## Осознанные отличия от Flutter-версии

| Что | Было во Flutter | Станет |
|---|---|---|
| Серия «3 верных подряд» | сбрасывается при выходе с экрана изучения | живёт до сдачи темы, не сбрасывается ни выходом, ни сменой дня |
| Что хранится | итог по теме (EF, интервал, дата) | каждый ответ в журнале, прогресс вычисляется |
| Где курсы | JSON-файлы в `Documents/polylingy/courses/` | документы в SQLite; импорт и экспорт JSON |
| id тем | индекс, потом короткий случайный | UUID у курсов, тем и упражнений |
| Верный ответ | только самооценка | самооценка, а если её нет — автопроверка (в текущих курсах оценка есть всегда, так что поведение то же) |
| Тема без упражнений | приложение падает | тему нельзя добавить, а при импорте выдаётся понятная ошибка |
| «Add topic» с JSON | принимается любой JSON-объект | проверяется структура, ошибка показывается в диалоге |

## Этап 1. Каркас и ядро

**Цель:** вся бизнес-логика на Kotlin и покрыта тестами. Приложения ещё нет.

Задачи:

1. Gradle-каркас:
   - `settings.gradle.kts`, `build.gradle.kts`, `gradle/libs.versions.toml`, wrapper;
   - toolchain JDK 25, проверить совместимость Gradle, Kotlin и плагинов (при проблемах — откат на JDK 21, решение записать);
   - `.gitignore` для `.gradle/` и `**/build/`.
2. Модуль `core`, Kotlin Multiplatform с единственной целевой платформой JVM.
3. Модели контента: `Course`, `Topic`, `Exercise`, `Explanation` (текст или HTML).
4. Модели журнала: `EventEnvelope`, `ZonedInstant`, `Event`, `AnswerSubmitted`, `AutoCheck`, `Rating`. Сериализация в JSON.
5. Правила:
   - `Sm2Policy` — перенос `sm2_policy.dart`;
   - сдача темы «серия до сдачи» — замена `ConsecutiveCorrectPolicy`;
   - `RandomTopicPicker` и `FixedTopicPicker`;
   - `AnswerChecker` — проверка пропусков, сейчас она живёт в `study_screen.dart`;
   - правило «верен ли ответ»: оценка, иначе автопроверка.
6. `replay()` и отбор тем на сегодня. С пометкой `TODO(perf)` про полный пересчёт.
7. Порты `CourseRepository`, `EventLog`, `Clock` и их реализации в памяти для тестов.
8. Сценарии использования: темы на сегодня, следующее упражнение, ответить, счётчики для списка курсов (new / to review / done today).
9. Тесты:
   - 64 текущих теста 1:1 на `kotlin.test`; тесты сдачи темы адаптировать под «серию до сдачи»;
   - новые тесты для `AnswerChecker` и `replay()`.

**Готово, когда:** `./gradlew :core:check` зелёный; правила читаются и проверяются без Flutter.

**Не входит:** SQLite, файлы, UI.

## Этап 2. Клиентское хранилище

**Цель:** курсы и журнал сохраняются в SQLite, курсы импортируются и экспортируются в JSON.

Задачи:

1. Модуль `client` (Kotlin Multiplatform, JVM) с SQLDelight.
2. Таблицы `course_document` и `journal_event`, как в архитектуре.
3. `SqlCourseRepository` и `SqlEventLog` — реализации портов ядра.
4. Импорт и экспорт JSON:
   - формат совместим с текущими файлами: `answer` строкой или объектом, `generalExplanationFormat`, необязательные `id` и `createdAt`;
   - недостающие UUID и версии генерируются;
   - проверка структуры с понятными сообщениями об ошибках: нет `topics`, тема без упражнений и т. п.
5. Пример курса: перенести `assets/sample_course.json` в ресурсы и импортировать при первом запуске, если курсов нет.
6. Тесты на SQLite в памяти:
   - сохранение и чтение;
   - рост `revision`;
   - импорт старого формата;
   - экспорт и обратный импорт без потерь.

**Готово, когда:** `./gradlew :client:check` зелёный.

**Не входит:** синхронизация, Android и iOS драйверы.

## Этап 3. Десктоп-приложение

**Цель:** приложение с тем же набором функций, что у Flutter-версии.

Задачи:

1. Модуль `app` (Compose Multiplatform, desktop):
   - `main()`, окно 832×720, минимальный размер 480×400;
   - `AppContainer`, который собирает БД, репозитории и сценарии ядра.
2. Навигация: список курсов → изучение → «всё на сегодня».
3. Экран списка курсов:
   - курсы по дате создания со счётчиками;
   - кнопка Start активна, только когда есть доступные темы;
   - New course (имя непустое, до 50 символов);
   - меню курса: Add topic (JSON), Rename, Remove с подтверждением, Import и Export.
4. Экран упражнения:
   - название темы, задание с `___` вместо пропусков;
   - поле ответа (несколько пропусков — через запятую), Enter отправляет.
5. Экран результата:
   - задание с подсветкой: верное зелёным, ошибка красным в виде «ответ → правильный»;
   - фраза и цвет по режиму (correct / partial / incorrect);
   - объяснение упражнения и общее объяснение темы, текст или HTML;
   - кнопки Incorrect и Correct, клавиши `1` и `2`, панель кнопок прижата к низу окна.
6. Удаление темы из меню экрана изучения с подтверждением.
7. Экран «All done for today» с возвратом в список.

**Готово, когда:** `./gradlew :app:run` открывает приложение, и по нему можно пройти весь сценарий из чек-листа ниже.

**Не входит:** редактор тем вместо JSON, новые экраны.

## Этап 4. Сверка паритета

**Цель:** убедиться, что новая версия делает всё, что старая, кроме осознанных отличий.

Задачи:

1. Пройти чек-лист паритета вручную в обеих версиях.
2. Сравнить расписание SM-2 на одинаковых сценариях ответов: даты следующих показов должны совпадать (с поправкой на «серию до сдачи»).
3. Исправить найденные расхождения.

**Готово, когда:** все пункты чек-листа отмечены, расхождения исправлены или записаны в «Осознанные отличия».

## Этап 5. Установщик для Windows

**Цель:** приложение ставится как обычное.

Задачи:

1. Настроить `nativeDistributions` в Compose Gradle-плагине: имя, версия, иконка, ярлык в меню Пуск.
2. `./gradlew :app:packageMsi`, установить и проверить запуск на чистом профиле.

**Готово, когда:** `.msi` устанавливается, приложение запускается без IDE и без отдельно установленной Java.

## Этап 6. Удаление Flutter

**Цель:** в репозитории остаётся только новая версия.

Задачи:

1. Удалить `lib/`, `test/`, `windows/`, `linux/`, `macos/`, `assets/`, `pubspec.yaml`, `pubspec.lock`, `analysis_options.yaml`, `.metadata`.
2. Убрать Flutter-правила из `.gitignore` и `.gitattributes`.
3. Переписать `CLAUDE.md`, `README.md` и `.claude/docs/architectural_patterns.md` под новую структуру и команды.

**Готово, когда:** `./gradlew check` зелёный, в репозитории нет Dart-кода, документация описывает новую версию.

## Риски

| Риск | Что делаем |
|---|---|
| JDK 25 не поддерживается какой-то частью сборки | проверяем на этапе 1, при проблемах берём JDK 21 |
| HTML в объяснениях: в Compose нет полноценного HTML-рендерера | поддерживаем простой набор тегов через `AnnotatedString.fromHtml`; в текущем примере курса HTML нет |
| Поведение правил незаметно разойдётся с Flutter | перенос тестов 1:1 и сверка расписаний на этапе 4 |

## Чек-лист паритета

Список курсов:

- [ ] При первом запуске появляется пример курса
- [ ] Курсы отсортированы по дате создания
- [ ] Счётчики «N new · N to review · N done today» верны
- [ ] Start неактивен, когда тем на сегодня нет
- [ ] New course: пустое имя нельзя, имя до 50 символов
- [ ] Rename course: те же ограничения
- [ ] Remove course с подтверждением
- [ ] Add topic: валидный JSON добавляет тему, невалидный показывает ошибку
- [ ] Import и Export курса (новое, вместо папки с файлами)

Изучение:

- [ ] Тема выбирается случайно среди доступных, упражнение — случайно внутри темы
- [ ] Пропуски `{0}`, `{1}` показываются как `___`
- [ ] Несколько пропусков вводятся через запятую, Enter отправляет
- [ ] Проверка без учёта регистра и пробелов по краям
- [ ] Режимы correct / partial / incorrect с цветом и случайной фразой
- [ ] Подсветка пропусков на экране результата, «ответ → правильный»
- [ ] Объяснение упражнения и общее объяснение темы (текст и HTML)
- [ ] Incorrect и Correct, клавиши `1` и `2`
- [ ] Тема сдаётся после 3 верных подряд (серия до сдачи)
- [ ] Даты следующего показа совпадают с таблицей SM-2
- [ ] Remove topic с подтверждением, прогресс остальных тем не меняется
- [ ] «All done for today» и возврат в список

Окно:

- [ ] Размер 832×720, минимум 480×400
