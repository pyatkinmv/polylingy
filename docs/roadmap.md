# Дорожная карта

Что нужно сделать, чтобы Polylingy можно было ставить и использовать каждый день, и что идёт после. Главное — итерация 1: путь к MVP, первому релизу **0.8.x alpha**.

Это план, а не описание сделанного: что уже есть, описано в `architecture.md`, `learning-model.md` и `content-format.md`.

## 1. Принятые решения

| Вопрос | Решение |
|--------|---------|
| Что такое MVP | Windows, один курс — English Usage Exercises (из Anki), один компьютер. Заменяет Anki для этого курса |
| Порядок платформ | Windows → простой сервер с БД и чистым API для синхронизации прогресса → Android → остальное (веб, iOS) |
| Синхронизация | Не в MVP, сразу после |
| Установка и обновление | Вручную: собранный MSI запускается поверх старого. Проверка новой версии через сервер — позже |
| Правка содержимого | В самом приложении не нужна: курс правится в файле (в Claude) и обновляется импортом с сохранением прогресса |
| Совместимость | С первого релиза (0.8.x) база и журнал не ломаются никогда: старые данные всегда читаются новой версией |
| Четыре кнопки оценки (Again/Hard/Good/Easy) | Не решено, входит в задачу 7 (ревизия абстракций) |
| Проверка курса на себе | Не задача приложения, а тестирование MVP; в список не входит |

## 2. Что уже есть и что мы проверили в коде

- **Обновление на Windows.** В `app/build.gradle.kts` у MSI задан постоянный `upgradeUuid`: новый MSI поверх старого заменяет программу, данные в `Documents/polylingy` не трогаются.
- **Миграции базы** SQLDelight уже работают (`1.sqm`, есть тест миграции с версии 1).
- **Журнал** версионируется (`schemaVersion`) и в каждом событии есть `deviceId` — основа будущей синхронизации: журнал только дописывается, значит события разных устройств просто объединяются.
- **Выбор упражнения** `RandomNotLast` не выдаёт подряд одно и то же.
- **Импорт курса** (`CourseService.import`): id в файле необязательны, недостающие выдаются случайные; `revision` из файла сбрасывается в 0; если id уже есть в базе, создаётся копия со свежими id и **прогресс не переносится**. Это главный пробел для итерации 1.
- **Данные разработки и установленной версии сейчас общие**: и `gradlew run`, и установленное приложение работают с `Documents/polylingy`.
- **Прогресс пересчитывается из журнала** при каждом открытии (`TODO(perf)` в `Replay.kt`); на большом журнале не проверялось.

## 3. Итерация 1 — MVP, релиз 0.8.x alpha

Цель: поставить на Windows, заниматься английским курсом, обновляться и править курс, ничего не потеряв.

### 3.1 Задачи

#### 1. Обновление курса по id и версии

**Зачем.** Курс правится в файле и загружается заново. Сейчас повторный импорт даёт копию без прогресса.

**Что делаем.**
- В корень файла курса — поле `courseVersion` (целое: 1, 2, 3…): версия содержимого, которую ставит автор. Не путать с `revision` (счётчик правок внутри приложения). Название можно заменить.
- Импорт файла, у которого id курса уже есть в базе:
  - `courseVersion` в файле **больше** сохранённой → обновление: содержимое заменяется, прогресс остаётся у топиков и упражнений с прежними id;
  - **равна или меньше** → отклонить с понятным сообщением («У вас версия 5, в файле 3»);
- Файл без id курса → новый курс (как сейчас), id выдаётся автоматически; экспорт потом пишет его в файл.
- Нет поля версии → считается 0, первое обновление возможно с любой версией ≥ 1.
- Что происходит при обновлении: топики с прежним id сохраняют прогресс и получают новый текст; новые топики «не начаты»; топик, которого в файле больше нет, исчезает из курса, а его ответы остаются в журнале и ни на что не влияют.
- Если курс правили внутри приложения (JSON-редактор), перед заменой — предупреждение, что правки будут заменены.
- Кнопка «Обновить курс из файла» (отдельно от «Импорт»).
- Конвертер Anki должен выдавать **стабильные id** (одни и те же при каждом запуске, например из хэша темы и номера упражнения), иначе обновление не сможет привязать прогресс.
- Формат: `courseVersion` — изменение формата курса, значит `formatVersion` 12, `docs/course.schema.json`, `docs/content-format.md`, примеры (см. «Course Format Changes» в CLAUDE.md).

**Готово, когда.** Тест: курс импортирован, даны ответы, импортирован файл с большей версией и изменённым текстом → прогресс на месте, текст новый; файл с меньшей версией отклонён; файл без id → новый курс.

#### 2. Раздельные данные релиза и разработки, один встроенный курс

**Зачем.** Установленная версия должна жить со своей чистой базой, своими бэкапами и только одним курсом, не мешая разработке.

**Что делаем.**
- Папка данных зависит от режима: установленное приложение — `Documents/polylingy`; запуск из Gradle (разработка) — `Documents/polylingy-dev` (через системное свойство, без жёсткой привязки к режиму в коде приложения).
- Текущие данные разработки (арабский, бурятский, тесты) переезжают в `polylingy-dev` один раз вручную.
- Английский курс — встроенный файл (ресурс) в установщике; при первом запуске пустой базы он импортируется вместо нынешнего учебного курса-образца. Других курсов в релизной базе нет.
- Резервные копии релиза лежат в его собственной папке данных (см. задачу 5).

**Готово, когда.** Установленное приложение открывается с одним курсом English Usage Exercises и не видит данных `polylingy-dev`; `gradlew run` не трогает `polylingy`.

#### 3. Гарантия совместимости

**Зачем.** База живёт годами; новая версия обязана открывать базу предыдущей и ничего в ней не терять.

**Что делаем.**
- «Эталонная» база первого релиза (небольшая, с курсом, ответами и настройками) хранится в репозитории как тестовый файл.
- Тест открывает эталон кодом текущей версии и проверяет: курсы читаются, журнал читается, прогресс считается так же, миграции применяются.
- После каждого следующего релиза добавляется ещё один эталон.
- Правило в `architecture.md`: изменения схемы — только миграциями; события журнала только добавляются, формат — через `schemaVersion`.
- Ручная проверка установки: собрать MSI версии X, поставить, позаниматься, собрать MSI версии X+1, поставить поверх → данные на месте.

**Готово, когда.** Тест-эталон есть и проходит; ручная установка поверх старой проверена один раз.

#### 4. Производительность на большом журнале

**Зачем.** Прогресс считается заново из всех событий при каждом открытии; курс на 5399 упражнений при ежедневной работе даст десятки тысяч событий.

**Что делаем.**
- Генератор синтетического журнала (~30 000 ответов по 333 топикам).
- Замер: открытие списка курсов, экрана курса, выбор следующего упражнения, ответ.
- Порог: больше ~0.3 с — делаем кэш (хранить свёртку прогресса, но по-прежнему выводимую из журнала: можно пересчитать с нуля).

**Готово, когда.** Замеры записаны (в `testing.md` или в тесте с порогом); если порог превышен — кэш реализован и тест на совпадение кэша с полным пересчётом проходит.

#### 5. Резервные копии базы

**Зачем.** Сбой диска или ошибка не должны уносить прогресс.

**Что делаем.**
- При запуске копия `polylingy.db` в `backups/` (в папке данных), имя с датой; хранятся последние 7–14.
- Не чаще раза в день; копирование безопасное (SQLite: через `VACUUM INTO` или копия при закрытом соединении).
- Перенос на другой компьютер — копирование папки `polylingy`; описать в инструкции.

**Готово, когда.** Тест: после запуска есть копия, лишние удаляются, копия открывается как база.

#### 6. Надёжность: ошибки и логи

**Зачем.** Тихое падение без объяснений недопустимо для ежедневной программы.

**Что делаем.**
- Необработанная ошибка показывается понятным окном (что случилось, что делать, где лог) вместо тихого закрытия или зависания.
- Логи (`logs/polylingy.log`, один файл в день, 14 дней) уже пишутся; добавить в приложение доступ к ним («Открыть папку логов»).
- Запоминание размера и положения окна.

**Готово, когда.** Искусственная ошибка в тесте показывает окно; в приложении есть путь к логам.

#### 7. Ревизия основных абстракций и study settings

**Зачем.** От неё зависят остальные решения (что показывать в статистике, как устроена практика). Нужно освежить в памяти и пересмотреть, как выбирается и засчитывается обучение, и что нужно именно для English Usage.

**Что разбираем** (четыре политики и связанное, см. `learning-model.md`):
- **Очередь** (`Queue`): какой топик брать следующим (`StartedFirst`, `Shuffled`, …), сколько новых в день.
- **Фокус** (`Focus`): оставаться на топике или переходить.
- **Выбор упражнения** (`ExerciseChoice`): `RandomNotLast`; что делать при 1–2 упражнениях в топике.
- **Оценка** (`GradingRule`): автооценка по результату; опечатка как «Hard»; нужны ли четыре кнопки (Again/Hard/Good/Easy) как настройка курса.
- **Освоение** (`MasteryPolicy`): когда топик считается пройденным за раунд.
- **Расписание** (`Scheduler`): SM-2, коробки, Anki-подобное; что подходит для топиков по 5–20 упражнений.
- **Study settings**: какие настройки показывать пользователю и с какими значениями по умолчанию для английского курса.

**Результат.** Документ с решениями (что оставляем, что добавляем, что убираем), затем реализация нужных вариантов. Эта задача — до статистики (8) и практики (9).

**Готово, когда.** Решения записаны в `learning-model.md`, нужные реализации и настройки сделаны, значения по умолчанию для английского курса выбраны.

#### 8. Вкладка статистики с календарём

**Зачем.** Видеть, сколько сделано и что осталось, как в Anki.

**Что делаем.**
- Новая вкладка/экран со статистикой.
- Календарь: по дням сколько ответов, сколько верных.
- На сегодня: сделано, новых осталось, повторов осталось.
- Минимально: никаких графиков сверх календаря и нескольких чисел.
- Данные выводятся из журнала (не хранятся).

**Готово, когда.** Тест с экраном и скриншотом; цифры совпадают с журналом.

#### 9. Экстра-практика: продумать (только дизайн)

**Зачем.** Сейчас нет способа позаниматься сверх расписания (повторить слабое, пройти ещё), а в Anki он есть.

**Что делаем.** Короткий документ: что это за режим (например, «ещё раунд по теме», «слабые места»), как он ложится в журнал и политики (не ломает расписание; ответы помечены), какой минимальный интерфейс. Реализация — вне итерации 1, если дизайн не окажется очень простым.

**Готово, когда.** Описание в `learning-model.md` или отдельном файле, с решением «делаем в итерации 1 / позже».

#### 10. Чистка курса English Usage (содержимое)

**Зачем.** В переведённом из Anki курсе есть некорректные или спорные упражнения.

**Что делаем.** Отдельная работа над содержимым (не код приложения): найти и исправить или удалить неверные ответы, сомнительные формулировки, дубли. Правки вносятся в файл и выкатываются обновлением курса (задача 1). Предложение: пройти курс скриптами-проверками и через `review-course`.

**Готово, когда.** Список найденных проблем закрыт; курс вышел с `courseVersion` 1 в составе релиза.

#### 11. Выпуск 0.8.x alpha

**Что делаем.**
- Версия `0.8.N` (номер растёт свободно, по мере изменений; первый выпущенный — тот, что станет эталоном совместимости); метка «alpha» в приложении (рядом с версией на списке курсов) и в имени установщика — внутри MSI слово не поместится, там только числа.
- Иконка приложения, название в меню «Пуск».
- Краткая инструкция: как поставить, обновить (MSI поверх старого), где данные и бэкапы, как перенести на другой компьютер.
- Сборка `./gradlew :app:packageMsi`, пробная установка на чистую папку и обновление поверх.

**Готово, когда.** MSI собран, установлен, открывается с одним курсом, обновление поверх сохраняет прогресс.

## 4. Дальнейшие итерации

### Итерация 2 — синхронизация и удобство
- **Сервер** с БД и чистым API: регистрация и вход; загрузка и получение событий журнала (объединение по id события и `deviceId`); хранение курсов с `courseVersion`.
- **Синхронизация в приложении**: кнопка и фоновая отправка; конфликты не возникают для журнала (только добавление), для курсов решает `courseVersion`.
- **Проверка новой версии**: файл версии на сервере, в приложении «Вышла 0.9.0, скачать».
- **Расширенная статистика**: слабые места (топики и упражнения с наибольшей долей ошибок), динамика.
- **Пометки упражнения**: «ошибка в курсе» (чтобы потом исправить), «отложить» (аналог suspend в Anki).
- **Четыре кнопки оценки** как настройка курса, если не вошли в итерацию 1.
- **Экспорт/импорт прогресса** файлом как запасной путь переноса.
- Экстра-практика (реализация), если не вошла в итерацию 1.

### Итерация 3 — Android
- Android-цель Kotlin Multiplatform, адаптация экранов под телефон (размеры, касание, клавиатура), хранилище, выбор файла.
- Скачивание курсов с сервера без ручного импорта.
- Проверка и звуковое/видео воспроизведение на Android (сейчас звук через JLayer — на JVM).

### Итерация 4 — остальное
- Веб-клиент.
- iOS (нужны Mac и аккаунт разработчика).
- Автоматическое обновление приложения (скачивание и запуск MSI, подпись).
- Напоминания и уведомления.
- Редактор курсов в приложении (добавление юнитов, топиков, упражнений), каталог курсов.

## 5. Открытые вопросы

- Название и формат поля версии курса (`courseVersion` предложен).
- Четыре кнопки оценки: нужны ли вообще (решается в задаче 7).
- Какой максимум правок курса внутри приложения допускать при существовании файла-источника (предупреждение при обновлении предложено).
- Что считать «пройденным за день» при статистике, когда сервер и несколько устройств появятся.
