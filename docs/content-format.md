# Формат содержимого курса

> Статус: **принято, версия 0.2.0; сейчас `formatVersion` 4** (звук, диалоги, подписи над словами). Формат курса: теория, упражнения, объяснения, импорт.
> **Формальное описание — [`course.schema.json`](course.schema.json)** (JSON Schema 2020-12), тесты держат его в согласии с кодом.
> Проверить готовый файл так, как его проверит импорт: `./gradlew :client:checkCourse -Pcourse=путь/к/course.json` (или `.zip`).
> Старый формат (`generalExplanation`, `task` с `{0}`) не поддерживается: новая версия пишется с нуля.
> Как ответы превращаются в прогресс — в `learning-model.md`.

## 1. Принципы

- **Автор описывает смысл, раскладку решает приложение.** В JSON нет размеров, отступов, процентов.
  Если понадобится управлять видом — только перечисления (`"size": "small" | "medium" | "large"`), не числа.
- **Тип задаётся на уровне упражнения**, не пункта. У каждого типа свои поля, своя отрисовка и своя проверка.
  Смешанных упражнений нет: если понадобится — заводим новый тип.
- **Код знает, *что такое* сопоставление; JSON говорит, *что* сопоставлять.** Ничего о конкретном курсе,
  языке или учебнике в коде нет.
- **Одна запись пропуска везде**: `{{ответ|другой вариант}}` — в тексте, в ячейке таблицы, в выборе.
- **Проверка при импорте строгая**: неизвестное поле или тип — ошибка с путём. Сохраняется только чистый курс.

## 2. Курс целиком

```json
{
  "formatVersion": 3,
  "id": "…",
  "name": "English Grammar in Use",
  "description": "Units on present and past tenses.",
  "theme": { "accent": "#2F6B5E" },
  "rules": { "preset": "ladder", "picker": { "type": "conveyor", "newPerDay": 10 } },
  "units": [
    { "id": "…", "title": "Present continuous", "subtitle": "I am doing",
      "theory": { "format": "blocks", "blocks": [ … ] },
      "topics": [
        { "id": "…", "title": "Things happening now",
          "explanation": { "format": "blocks", "blocks": [ … ] },
          "exercises": [ { "id": "…", "type": "gaps", … } ] } ] }
  ]
}
```

- Курс содержит **либо** `units`, **либо** `topics` (плоский курс), не оба; хотя бы что-то одно.
- `name` — до 50 символов. `description` — необязательный `Inline` (без пропусков), строка под названием курса.
- `extraKeys` необязателен: клавиши, которых нет на обычной клавиатуре, — буквы языка курса (`["ө", "ү", "һ"]`).
  Пока в поле для ответа (пропуск, ячейка таблицы, ответ `expand`, исправление `fix`) стоит курсор, над ним в маленькой
  светлой плашке показаны эти клавиши; нажатие вставляет текст клавиши туда, где курсор; плашка исчезает, когда поле
  теряет фокус (щелчок мимо поля). Не больше 12 клавиш, каждая 1–8 символов, без повторов. Регистр не важен: проверка
  его не различает, поэтому заглавных клавиш не нужно. Список можно пополнять чем угодно, что вводится текстом.
- `theme` необязателен; без него — цвет приложения по умолчанию. `accent` — цвет вида `#2F6B5E`: кнопки, отметки, буквы разделов.
- `rules` — политики курса: набор (`quick`, `ladder`, `sm2`) и замены отдельных частей, формат в `learning-model.md`,
  раздел 5. Без `rules` — набор `ladder`. В нём же:
  - `grading.typos` — прощать ли одну опечатку на пункт; по умолчанию `true`;
  - `picker.newPerDay` — сколько новых топиков можно начать за день (целое ≥ 1); нет поля — нет лимита;
  - `picker.exercise` — какое упражнение топика показывать: `random-not-last` (по умолчанию), `in-order` (по кругу в порядке курса),
    `missed-first` (сначала то, где ошиблись в прошлых раундах и верного ответа с тех пор не было, самое давнее первым, но не в том
    раунде, где ошиблись; иначе по порядку; подробно — `learning-model.md`, раздел 7).
    Подробно — `learning-model.md`, «Дневной лимит новых топиков».
- `rules` файла — только **начальные** настройки: при импорте они копируются в настройки курса, дальше их меняет
  пользователь на экране «Study settings». Экспорт пишет в `rules` текущие настройки (`architecture.md`, раздел 5).
- `id` — UUID. Экспорт пишет их всегда. При импорте отсутствующие, неверные и повторяющиеся id заменяются новыми.
  Если хоть один id курса уже есть в приложении, импорт создаёт **копию** со всеми новыми id.
- Название, уже занятое другим курсом (без учёта регистра), получает номер: «English Grammar in Use (2)».
- `version` — **версия курса** (целое ≥ 1; нет поля — 1): 1 у первой редакции, на 1 больше после каждого изменения документа,
  всё равно где сделанного: в приложении (правка юнита, топика, названия) или в новом файле автора. При импорте она сохраняется как
  в файле; экспорт пишет текущую, так что файл, сделанный из курса, уже несёт её. Каждый ответ в журнале помнит версию, на которой дан
  (`courseVersion` в записи; в таблице курсов столбец `course_version`). Обновление курса («Update from file…» в меню курса):
  файл с **тем же** `id` курса заменяет содержимое сохранённого курса, если его `version` **больше**, иначе отказ с объяснением
  («в файле 5, в приложении уже 6»: если курс правили в приложении, возьмите экспорт или поставьте в файле число больше); файл другого
  курса или с id, принадлежащим другому курсу, тоже отказ. После обновления у курса версия файла. Прогресс остаётся у топиков и
  упражнений с прежними id, новые начинаются с нуля, ответы на исчезнувшие остаются в журнале и ни на что не влияют; настройки
  курса не меняются, название берётся из файла. Поэтому при каждом обновлении **id внутри курса должны оставаться теми же**.
  Обычный импорт файла с уже известным id по-прежнему создаёт копию.
- `createdAt` и `updatedAt` пишет экспорт; в файле они необязательны. При импорте `updatedAt` сбрасывается, `createdAt` сохраняется
  (нет его — время импорта).

## 3. Текст с разметкой (`Inline`)

Все текстовые поля — это `Inline`: строка с маленькой разметкой.

| Запись | Значит |
|---|---|
| `**жирный**` | выделение (формы, на которые смотреть) |
| `*курсив*` | курсив |
| `==выделено==`, `=={2}выделено==` | выделение: тон — номер метки палитры, 1–5, в скобках после открывающих `==` (без скобок — первая). Тоны это роли, а не цвета: какого цвета метка, говорит палитра курса, а как она нарисована (фоном или подчёркиванием) — стиль курса. Для корня и окончания, образца в правиле. `\=` — буква `=`. В тексте с подписями над словами выделение не рисуется |
| `{{ответ}}` | пропуск; только в полях упражнений |
| `{{had missed}}[[miss]]` | пропуск с подсказкой: `[[…]]` сразу после `}}`, одна строка; пустое поле показывает её серым. Только в пропусках `gaps` |
| `{{’s working\|is working}}` | пропуск с несколькими верными вариантами |
| `[老师](lǎoshī)` | **подпись над словом**: мелкий текст над ним — как читать, ударение, перевод |
| `\n` | перенос строки |
| `\*`, `\{`, `\}`, `\|`, `\[`, `\]`, `\\` | сам символ, без разметки |

Подпись — общая возможность, приложение не знает, что в ней. В настройках курса её можно выключить
(«Show annotations over text», раздел 6 `learning-model.md`): тогда видны только сами слова. `[` без `…](…)` после
него — обычный символ. Подписи работают везде, где есть `Inline`: в теории, заданиях, вариантах выбора, плашках `order`,
сторонах `match`. В пропуски их не пишут.

Текст без пробелов (китайский, японский) переносится по любому иероглифу; знаки препинания остаются с предыдущим.
**Слова с подписями пишут без пробелов** между ними: `[你](nǐ)[是](shì)[学生](xuésheng)。` — пока подписи видны, между
словами есть небольшой зазор, а когда их выключат, текст читается как обычный китайский, без лишних пробелов.
Исключение — `order`: там пробел отделяет плашки (`"[我](wǒ) [不](bú) [是](shì)"`).

Разметка проверяется при импорте: незакрытые `**`, `{{` — ошибка. Пропуск вне упражнения — ошибка.
Каждый вариант ответа в пропуске — не длиннее **60 символов** (`MAX_BLANK_LENGTH`): поле ввода растёт вместе с текстом
до этой длины и дальше символы не принимает, поэтому верный ответ всегда должен в него помещаться.
Пустой текст — ошибка везде, кроме ячеек таблиц.

## 4. Содержимое (`Content`) и блоки теории

Теория юнита и объяснения — это `Content`:

```json
{ "format": "blocks", "blocks": [ … ] }
```

Пока реализуется только `blocks`. **TODO:** `markdown`, `html` — когда понадобятся; в модели под них
оставлено место (`sealed interface Content`).

| Блок | Поля | Как раскладывает приложение |
|---|---|---|
| `section` | `id?`, `label?` («A»), `title?`, `blocks` | с `label` — буква на полях слева, содержимое справа (как в грамматиках с разделами A, B, C); без `label` — заголовок `title` над содержимым во всю ширину; `id` — UUID, только у разделов, на которые ссылаются |
| `text` | `text`, `role?` | абзац; `role: "lead"` — вводная строка раздела: курсив крупнее, цветом обычного текста |
| `situation` | `blocks`, `aside?` (блок, обычно `image`), `look?` (`card` по умолчанию, `plain`), `frame?` (рамка письма, статьи или вырезки: `email`, `article`, `newspaper`, как `look` упражнения) | мягкая карточка без линии (`card`) или без рамки (`plain`: картинка просто стоит рядом с абзацем); `aside` справа, размер по `size` картинки: `small` — квадратная миниатюра 120 dp (обрезается по центру) слева от текста, `medium` — 180 dp в своих пропорциях, `large` (и картинка без `size`) — до 35 % ширины и не шире 280 dp; на узком окне картинка уходит вниз; с `frame` вместо карточки рисуется рамка с заголовком, внутри неё те же `blocks` и `aside`: письмо прямо в теории |
| `image` | `src`, `alt`, `caption?`, `size?` (`small`, `medium`, `large`), `description?`, `made?` (до 2000 знаков каждое, не показываются) | по центру, со скруглёнными углами, размер словом (те же слова, что у `aside` упражнения): `small` до 160 dp, `medium` (по умолчанию) до 300 dp, `large` до 560 dp, но не шире колонки; высота по пропорциям картинки |
| `table` | `head?`, `appearance?` (вид таблицы, ниже), `rows` (ячейка — `Inline` или `{ "text"?, "rowSpan"?, "audio"? }`) | колонки по содержимому; шире места — прокрутка внутри рамки; ячейка со звуком — кнопка ▶ перед текстом (текст можно не писать); без `appearance` таблица на всю ширину места, в мягкой карточке, с тонкими линиями между строками, шапка обычная. `appearance` — необязательный объект, поля которого меняют только вид: `widthOfTable` (`fullWidth` по умолчанию — колонки делят всю ширину; `onlyAsWideAsContent` — каждая колонка по ширине своего текста), `background` (`card` по умолчанию; `none` — без карточки), `headerRow` (`plain` по умолчанию; `highlighted` — шапка залита светлым тоном акцента), `highlightedColumns` (номера колонок с 0: жирным на светлой подложке), `stripedRows` (каждая вторая строка на подложке, по умолчанию `false`), `linesBetweenRows` (линии между строками, по умолчанию `true`) |
| `dialogue` | `look?` (`lines` по умолчанию, `bubbles`), `portraits?` (`{ "who", "image" }`: картинка говорящего, `who` как в реплике), `lines`: `{ "who"?, "text", "audio"?, "translation"? }` | разговор строками: ▶ (если есть звук), имя слева, реплика; перевод — мелко серым под ней; `bubbles` — облачка: реплики первого говорящего слева, второго справа, остальных слева; рядом с облачком круглый портрет (если он есть в `portraits`), без портрета над репликой стоит имя |
| `track` | `title`, `audio` | запись целиком, как в книге значок наушников у раздела («Дорожка 1:03»): кнопка ▶ и название в рамке. Длинная запись играет в плеере внизу окна (см. раздел 7) |
| `video` | `title`, `url` (`https://…`), `note?` | видео в интернете: рамка с названием и подсказкой; нажатие открывает адрес в браузере. Курс не хранит видео, только указывает на него; по адресу его не скачать и не проверить |
| `quote` | `text`, `who?`, `aside?` | реплика в облачке; `aside` с картинкой слева |
| `examples` | `numbered?` (по умолчанию `false`), `items`: `{ "text", "not"?, "translation"?, "audio"? }` | список (с `numbered` — цифры 1, 2, 3 акцентным цветом вместо точек); `not` серым в скобках: «(*not* I try)»; перевод мелко серым под примером; со звуком вместо точки — ▶ |

**Перевод** (`translation` у реплики и примера) показывается всегда, когда он записан: где он нужен, решает курс, а не
настройка. Не пишите его там, где упражнение проверяет понимание или просит перевести.
| `words` | `words` | слова колонками, число колонок по ширине |
| `tip` | `kind?`, `title?`, `aside?`, `blocks` | плашка с иконкой и подписью; `kind`: `tip` (по умолчанию, «Tip»), `note`, `rule`, `warning`, `fact` («Знаете ли вы?», синий), `culture` («Традиция», терракотовый). Цвет акцента курса, у `warning` — жёлто-коричневый; свои цвета курс не задаёт; `title` вместо подписи вида («Обо»); `aside` — блок, обычно картинка, рядом с плашкой, как у `situation` |
| `grid` | `columns?` (2–4, по умолчанию 2), `blocks` | блоки рядом в `columns` колонок, строка за строкой; любые блоки внутри (карточки слов, пара таблиц, две плашки); на узком окне (двух колонок — меньше 560 dp, трёх и четырёх — меньше 760 dp) блоки встают друг под другом |
| `seeAlso` | `links`: `{ "section": "…id" }` / `{ "unit": "…id" }` | строка ссылок |

Набор заточен под первый учебник; проверим его на других книгах и будем расширять (с повышением версии, раздел 9).

## 5. Упражнения

### Слои

Любое упражнение рисуется одинаково — слоями, сверху вниз. Тип упражнения решает только **тело**; остальные слои —
общие поля, одинаковые у всех типов, и они ничего не знают друг о друге и о теле.

```
instruction                                задание                                  все типы
wordBank                                   слова-подсказки, только читать          gaps, pictures, expand
┌ look ─────────────────────────────────┐  рамка с шапкой: письмо, статья          все типы
│ ┌ aside ┐  ┌ тело ──────────────────┐ │  картинка рядом с телом                 все типы
│ │       │  │ пункты типа             │ │  тело: только свои пункты               тип
│ └───────┘  └─────────────────────────┘ │
└───────────────────────────────────────┘
explanation                                после проверки                           все типы
```

```json
{ "id": "…", "type": "gaps",
  "instruction": "Complete the email. Past simple or past continuous.",
  "look":  { "type": "email", "from": "Maya", "to": "Theo", "subject": "The strangest commute ever" },
  "aside": { "image": { "src": "images/tram.png", "alt": "A tram stop", "caption": "My stop" }, "side": "left", "size": "small" },
  "wordBank": ["wait", "drop"],
  "items": [ … поля типа … ],
  "explanation": { "format": "blocks", "blocks": [ … ] } }
```

| Поле | Что это | У кого | Обязательно |
|---|---|---|---|
| `instruction` | задание, `Inline` | все | нет |
| `audio` | звук, который слушают перед ответом: большая кнопка ▶ над рамкой; играет только по нажатию | все | нет |
| `video` | видео, которое смотрят перед ответом: `{ "title", "url" (`https://…`), "note"? }`; карточка над рамкой, нажатие открывает адрес в браузере | все | нет |
| `generated` | `true`, если упражнение сгенерировано, а не написано автором курса; по умолчанию `false`. Нигде не показывается, нужно только чтобы отличать в файле | все | нет |
| `wordBank` | слова для подсказки, строки; рисуются плашками над рамкой, нажимать их нельзя | `gaps`, `pictures`, `expand` | нет |
| `passage` | страница блоков, которую читают перед ответом: диалог, рассказ, письмо, цитаты. Рисуется над рамкой теми же блоками, что теория (диалог с портретами, текст, `examples`), поэтому упражнение стоит на своих ногах и не отсылает к теории. Только оригинал: перевод выдал бы ответы. Формат как у `explanation`: `{ "format": "blocks", "blocks": [ … ] }` | все | нет |
| `look` | рамка с шапкой, см. ниже | все | нет — без рамки |
| `aside` | одна картинка рядом с телом, см. ниже | все | нет |
| `explanation` | объяснение после проверки (раздел 6) | все | нет |

**Правила, чтобы слои не конфликтовали:**
1. Рамка рисует только рамку и шапку, тип — только свои пункты. Тип ничего не знает о рамке и картинке.
2. Одна рамка и одна картинка на упражнение, обе необязательны.
3. Картинка стоит **внутри рамки**, если рамка есть (фото — часть статьи), и **рядом с пунктами**, если рамки нет.
4. Пункты внутри рамки остаются пронумерованными; **упражнение из одного пункта номера не показывает** —
   так один пункт с многими пропусками становится связным текстом (письмо, статья).
5. Банк слов — над рамкой: это инструмент ученика, а не часть письма. Плашки, которые нажимают (`order`, `match`), —
   это тело, а не банк слов.
6. Незнакомая рамка из файла новее — показывается как «без рамки», упражнение работает.

**`look` — рамки**

| `type` | Поля | Как выглядит |
|---|---|---|
| `email` | `from` (обязательно), `to`, `subject` (`Inline`, обязательно) | тема крупно; кружок с первой буквой отправителя, имя, «to …»; линия; тело |
| `article` | `title` (`Inline`, обязательно), `source` | строка источника капителью (`notes-from-the-road.blog`), заголовок с засечками; линия; тело |
| `newspaper` | `headline` (`Inline`, обязательно; `
` — перенос строки), `source` | газетная вырезка: строка источника капителью (газета, день), заголовок крупными жирными засечками на сероватой бумаге в рамке из точек; линия; тело. Для упражнений вида «посмотрите на заголовок и ответьте» |

Новая рамка — новое значение `type` (и повышение `formatVersion`).

**`aside` — картинка**

| Поле | Значения | По умолчанию |
|---|---|---|
| `image` | `{ "src", "alt", "caption" }`, как в теории | обязательно |
| `side` | `left`, `right`, `top`, `bottom` | `right` |
| `size` | `small`, `medium`, `large` | `medium` |

Размер — словами, не пикселями: слева и справа картинка занимает ¼, ⅓ или ½ ширины, сверху и снизу — ⅓, ½ или всю
ширину (по центру), но не больше потолка в dp, чтобы широкое окно не растягивало картинку: сбоку 160 / 220 / 320, сверху и снизу 220 / 340 / 520. Высота — по пропорциям самой картинки: не обрезается и не растягивается. Подпись — под картинкой.
Слева и справа получаются две колонки: текст не обтекает картинку снизу. В узком окне (уже 560 dp) `left` и `right`
становятся `top`. Аватар с именем — это просто картинка с подписью `**Dr Ana Ruiz**\ndirector of the lab`.

### Типы

Каждый пропуск, место выбора, пара, предложение или помеченное слово — **один пункт** для проверки:
`CORRECT` / `TYPO` / `WRONG` (`learning-model.md`, раздел 3). Ответ в пропуске — не длиннее 60 символов.

**`gaps` — пропуски в предложениях**
```json
{ "type": "gaps",
  "example": "Please be quiet. I **’m working**. (work)",
  "wordBank": ["sing", "wear", "get"],
  "items": [
    { "text": "Listen! Somebody {{is singing}}[[sing]] next door." },
    { "text": "I {{’m not reading|am not reading}}[[not / read]] it now.",
      "note": "Negative: am / is / are + **not** + -ing." } ] }
```
В каждом `text` хотя бы один пропуск, у каждого может быть своя подсказка `[[…]]` (серым в пустом поле; после проверки под предложением одной строкой, через « / »). Опечатки — по настройке курса. Связный текст (письмо, статья) — это **один
пункт с многими пропусками**: номер не показывается, подсказки пишутся прямо в тексте `{{was waiting}} (wait)`,
абзацы — пустой строкой `\n\n`. Пары a / b — один пункт из двух строк `"a  …\nb  …"`; там, где слово не нужно, ответ `–`.

**`choice` — выбор формы**

Место выбора записывается одним из двух способов:
```json
{ "type": "choice",
  "items": [
    { "text": "Look, it {{’s raining}} again.", "options": ["rains", "’s raining"] },
    { "text": "Thanks, and I {{apologise|’m apologising}} for not writing. I {{admit|’m admitting}} it was hard." } ] }
```
- с `options`: ровно один пропуск, в нём только верный ответ, он входит в `options`; вариантов ≥ 2;
- без `options`: сколько угодно мест прямо в тексте, каждое перечисляет свои варианты, **верный — первым**; вариантов ≥ 2, без повторов. Варианты, которые все являются числами, показываются по возрастанию, остальные перемешиваются.

Варианты показываются «пилюлями» на месте пропуска, в случайном порядке. Пункт — каждое место. Проверка точная, опечаток нет.

Необязательное `"mark": "ب"` у пункта — кусок текста, о котором пункт («сколько раз встречается ب»). После проверки пункт
можно выбрать нажатием, и в тексте рамки (`look`: заголовок `newspaper`, заголовок `article`, тема `email`) закрашиваются
все места этого куска; сразу после проверки выбран первый пункт с `mark`. Приложение не знает, что это за текст, оно только ищет его.

**`pictures` — карточки с картинкой и пропуском**
```json
{ "type": "pictures", "wordBank": ["cook", "swim"],
  "items": [ { "image": { "src": "images/1-cook.png", "alt": "A man at a stove" },
               "text": "He {{’s cooking|is cooking}}." } ] }
```
Карточки идут сеткой, число колонок по ширине окна.

**`table` — пропуски в таблице**
```json
{ "type": "table", "head": ["", "positive", "question"],
  "rows": [ ["I", "I {{am}} working", "{{Am}} I working?"] ] }
```
Хотя бы один пропуск во всей таблице; строки одной длины.

**`match` — сопоставление**
```json
{ "type": "match",
  "pairs": [ ["I’m tired,", "so I’m going to bed."], ["Be quiet!", "The baby is sleeping."] ],
  "extra": ["It rains a lot here."] }
```
Сторона пары — `Inline` или `{ "image": … }`. Пар ≥ 2, стороны не повторяются. Пункт — пара.
Если слева картинки, они рисуются квадратными карточками одного размера (128 dp): картинка вписывается целиком, по центру, без обрезки (квадратная заполняет карточку точно), номер пары — значком в углу. Упражнение тогда идёт строками: справа в каждой строке карточка с подписью, высотой с картинку, так что столбцы одной длины.

**Звук пункта в `choice`.** У пункта (`items[i]`) есть необязательное `"audio"` — запись одного слова: перед пунктом стоит кнопка ▶
(короткая запись играет сама). Так делают «послушайте слово и выберите»: `{ "text": "{{үдэн}}", "options": ["үдэн", "үүдэн"], "audio": "audio/word-01.mp3" }`.
Звук упражнения (`audio` у самого упражнения) остаётся одним на всё упражнение.

**`order` — собрать предложение**
```json
{ "type": "order",
  "items": [ { "answer": "Is it raining now?", "accept": ["Is it now raining?"] } ] }
```
Плитки — слова из `answer`, перемешанные; знак в конце предложения (`.?!…。？！`) — не плитка, он стоит на месте.
`accept` — другие верные порядки из тех же плиток и с тем же знаком в конце. Проверка точная.
Вместо `answer` можно дать `parts` — целые фразы в правильном порядке (например, реплики диалога): плитки — эти фразы,
знака в конце нет, `accept` не используется. `{ "parts": ["你好！", "你好！你是老师吗？", "不是，我是学生。"] }`

**`sort` — разложить по группам**
```json
{ "type": "sort",
  "instruction": "К какому ряду относятся слова?",
  "groups": [
    { "title": "задний ряд", "items": ["шатар", "ном"] },
    { "title": "передний ряд", "items": ["үдэр", "гэр"] } ] }
```
У каждой группы название (`Inline`) и слова, которые к ней относятся; слово лежит ровно в одной группе (без учёта регистра).
Групп 2–6, слов всего 3–24. Приложение показывает слова одной перемешанной кучей над группами: ученик нажимает слово, потом
группу, куда оно относится; нажатие на слово в группе возвращает его в кучу. Каждое слово — один пункт: верно, если лежит в своей
группе; после проверки неверное слово показано с названием группы, где ему место.

**`expand` — развернуть заметки в ответ**
```json
{ "type": "expand",
  "wordBank": ["constantly / check / phone", "always / borrow / charger"],
  "example": "**A** Where are my keys again?\n**B** You’re **forever losing your keys**.",
  "items": [
    { "text": "**A** Can I take yours? Mine’s flat.\n**B** You’re {{always borrowing my charger}}.",
      "keys": [["always", "borrowing", "charger"]],
      "note": "After *always* the verb takes **-ing**." } ] }
```
В `text` ровно один пропуск — **образец ответа** (варианты через `|`, до 150 символов); ученик пишет ответ целиком.
`keys` — допустимые порядки ключевых слов (или фраз) **в тех формах, которые нужны в ответе**; все порядки из одних и тех же слов.
Ответ верен, если это образец, или в нём есть ключевые слова одного из порядков, **в этом порядке, с любыми словами между ними**
(`TextMatcher.keys`); фраза из ключа должна стоять подряд; одна опечатка в одном ключевом слове — `TYPO`.
Образец обязан сам проходить `keys` — иначе ошибка импорта. Неверный ответ получает одну строку причины:
`Not found: borrowing` (каких ключевых слов нет — неверная форма тоже «нет»), иначе `Wrong order: continually before interrupting`
(первая пара не в том порядке), иначе `More than one typo`. Всё остальное объясняют `note` и `explanation`.
Диалог — это просто жирные имена и переносы строк, отдельного компонента нет.

**`fix` — найти и исправить**
```json
{ "type": "fix",
  "items": [
    { "text": "We {{had been driving}} for six hours when the car {{had been breaking => broke}} down." },
    { "text": "a  Once you {{signed => ’ve signed|have signed}} the form, you can’t cancel.\nb  Once she {{signed}}, the deal was done." } ] }
```
Пропуск здесь — **помеченное слово**: `{{как есть}}` — оно верное, `{{неверное => исправление|другое исправление}}` — неверное.
Каждое помеченное слово — пункт. У слова ✓ (оставить, так в начале) и поле для исправления; введённое исправление зачёркивает слово.
Верно: верное слово оставлено (или введено то же самое); неверное исправлено одним из вариантов (опечатки — как в пропусках).
Ошибка: неверное оставлено, или верное «исправлено». «Какое из пары неверно» — тот же `fix` с двумя строками в пункте;
что неверно ровно одно, говорит задание, приложение это не проверяет.

## 6. Объяснения

| Где | Поле | Формат | Когда видно |
|---|---|---|---|
| Пункт | `note` | `Inline`, одна-две строки | под пунктом, если он неверный |
| Упражнение | `explanation` | `Content` | под упражнением после проверки |
| Топик | `explanation` | `Content` | после проверки, под объяснением упражнения (если оно есть); над ним заголовок — название топика |

«Проверить» нажимается, когда есть ответ на каждый пункт (все пропуски заполнены, везде выбран вариант, все пары
соединены, все плитки на местах; в `fix` — всегда). До этого кнопка серая.
После проверки упражнение остаётся на месте и размечается (верно / опечатка / ошибка). Правильный ответ не пишется
второй раз там, где он уже на экране: в `choice` верный вариант обводится зелёным с галочкой, выбранный неверный краснеет;
в `order` из целых фраз (`parts`) каждое место показывает, что поставили, и у неверных справа «→ что должно стоять»;
в остальных типах правильный ответ стоит под пунктом.
объяснение — ниже, свободная страница из тех же блоков, что теория. Показывается после каждой проверки, и при верном ответе тоже.
Может ссылаться на раздел теории (`seeAlso`).

### Ссылки на теорию

Ссылка указывает на раздел по его `id`, а не по букве: буквы бывают не во всех книгах и повторяются в каждом юните.

```json
{ "type": "section", "id": "5a3f1e2d-7b6c-4d8e-9f00-1a2b3c4d5ea1", "label": "A", "title": "Happening now", "blocks": [ … ] }
{ "type": "seeAlso", "links": [ { "section": "5a3f1e2d-7b6c-4d8e-9f00-1a2b3c4d5ea1" }, { "unit": "…id юнита" } ] }
```

- `id` раздела — UUID, необязательный: ставится только у разделов, на которые кто-то ссылается. Уникален в пределах курса.
- `{ "section": … }` ведёт в раздел теории любого юнита курса; `{ "unit": … }` — в начало теории юнита.
- При импорте проверяется: id разделов не повторяются, каждая ссылка ведёт в существующий раздел теории или юнит.
- Приложение показывает ссылку как «B · Started, not finished» (буква и название раздела), открывает теорию на этом разделе
  и ненадолго подсвечивает его; «Назад к упражнению» возвращает к проверенному упражнению.
- Копия курса при повторном импорте получает новые id юнитов, ссылки `unit` переводятся на них; id разделов остаются.

## 7. Картинки, звук и импорт

Два вида файла:

- **JSON** — один `course.json`, картинки только по `https://…`.
- **Zip** — `course.json` в корне и папка `images/`; `src` — путь внутри архива (`images/u1-cycling.png`)
  или `https://…`.

Картинки и звук по URL приложение скачивает при импорте и хранит у себя: курс работает без сети.
**Звук** — файлы `.mp3` или `.wav`, в архиве обычно в `audio/` (`audio/u1-d1-1.mp3`). Звук привязан к тому, что записано
целиком: реплике, слову в таблице, упражнению — не к отдельному иероглифу (тон в слове зависит от соседей).
Звук играет только по нажатию ▶; новый звук останавливает предыдущий. Не скачался — предупреждение, кнопка молчит.
**Плеер.** Звук короче 6 секунд (слово, фраза) играет сам, и повторное нажатие ▶ запускает его заново. Длинная запись
(дорожка учебника на десятки секунд и больше) открывает закреплённый внизу окна плеер: пауза и продолжение, полоска, по
которой можно щёлкнуть или протащить к любому месту, время `0:12 / 0:29`, крестик. Кнопка записи в тексте при этом
показывает паузу и ставит запись на паузу сама. Название в плеере — `title` блока `track`. Запись держится в памяти
расшифрованной: перемотка мгновенна, но в памяти умещается примерно 150 МБ звука.
**Письмо справа налево.** Направление текста приложение определяет по первой букве (арабский, иврит): такие строки с
пропусками, места выбора и плитки упражнения «по порядку» идут от правого края, а буквы этих письменностей рисуются
на четверть крупнее латинских. Ничего для этого в курсе писать не нужно.
`alt` обязателен — подпись для доступности и запасной текст, если картинка не загрузилась.
Необязательные `description` (что именно на картинке: предметы, цвета, расположение, надписи дословно) и `made` (как сделана: промпт модели или скрипт и данные схемы) читают редакторы и инструменты; приложение их не показывает, но хранит при экспорте. Не длиннее 2000 знаков.
Путь в `src`, которого нет в архиве, — ошибка импорта.

Юнит или топик можно править в приложении как JSON-фрагмент того же формата (`CourseParts`). Пока картинки при этом
не подгружаются: новая картинка по URL или путь, которого нет среди картинок курса, показываются подписью `alt`.

## 8. Как это устроено в коде

```
content/          чистый Kotlin, без Compose и SQL:
                  Inline, Image, Side, Cell, Block, Content, Exercise, Response, разбор и validate()
content-compose/  отрисовка: блоки, ExerciseView на каждый тип, ContentTheme (акцент, шрифты)
core/             зависит от content: курсы, журнал, политики, ExerciseChecker на каждый тип
client/           импорт/экспорт файлов и zip, картинки, SQLite
app/              экраны, собирает всё вместе
```

`content` и `content-compose` ничего не знают о курсах, журнале и политиках — их можно вынести в отдельную библиотеку.

```kotlin
/** Тип упражнения — подкласс; общие поля (слои) — в самом интерфейсе. JSON плоский: `{"id", "type", "instruction", "look", …поля типа}`. */
@Serializable sealed interface Exercise {
    val id: Uuid; val instruction: Inline?; val explanation: Content?
    val look: Look?; val aside: Aside?; val wordBank: List<String>   // слои 2–4, у всех типов
    val itemCount: Int
    fun validate(at: Path): List<Problem>
}

@Serializable @SerialName("match")
data class Match(override val id: Uuid, …, val pairs: List<List<Side>>, val extra: List<Side> = emptyList()) : Exercise

// content-compose: только отрисовка; что верно, не знает — получает готовые checks.
// ExerciseView рисует слои (instruction, WordBank, Framed(look, aside) { тело }, explanation); тип рисует только тело.
@Composable fun ExerciseView(exercise: Exercise, response: Response, checks: List<ItemCheck>?, onChange: (Response) -> Unit, …)

// core: только проверка; как это выглядит, не знает
fun interface ExerciseChecker<E : Exercise, R : Response> {
    fun check(exercise: E, response: R): List<ItemCheck>   // опечатка — всегда TYPO; засчитывать ли её — grading.typos
}

/** Результат пункта и правильный ответ для показа: при опечатке — тот вариант, к которому ответ был близок. reason — строка причины (expand). */
data class ItemCheck(val result: ItemResult, val rightAnswer: String, val reason: String? = null)
```

Выбор вида и чекера — исчерпывающий `when` по sealed-классу (`ExerciseView`, `Checking.check`): забытый тип
не скомпилируется. В журнал идут только `ItemResult`, правильный ответ для показа берётся из упражнения заново.

**Новый тип упражнения — ровно пять мест**, больше нигде:
модель с `validate()` в `content`, вид тела в `content-compose` (ветка в `ExerciseView`), `ExerciseChecker` в `core`,
образец в тестах (`Samples`) и определение в `docs/course.schema.json` (раздел 10 — тест не даст забыть).
Экран упражнения, слои, журнал, политики и `replay()` о типах не знают. Новая рамка — класс в `Look` и ветка в `Framed`.

**Журнал** хранит ответ и результат проверки по пунктам на момент ответа
(`response` + `results`, у события свой `schemaVersion`). `replay()` старые ответы не перепроверяет,
поэтому правка упражнения не переписывает прошлое.

## 9. Проверка и версия формата

### Проверка при импорте

1. **Форма** — декодирование kotlinx (`ignoreUnknownKeys = false`): поле `"type"` выбирает класс,
   неизвестное поле или тип — ошибка с путём:
   `units[0].topics[2].exercises[4]: unknown field "optoins" in "choice"`.
2. **Смысл** — `validate()` каждого типа и общие правила (разметка, `alt`, файлы в zip, ссылки `seeAlso`).
   Собираются **все** ошибки сразу; пока они есть, курс не сохраняется.

Тот же JSON хранится в базе и пишется при экспорте — формат один.

### Схема и проверка файла

`docs/course.schema.json` — формальное описание формата (JSON Schema 2020-12): какие объекты, какие поля, какие
значения. Его можно отдать любому, кто пишет курс (в том числе Claude в новой сессии), и им можно проверять файл
любым валидатором схем. Схема не может сказать всего: разметку `Inline`, число пропусков в пункте, ссылки на
существующие разделы, образцы `expand`, файлы в архиве проверяет только приложение. Поэтому окончательная проверка —
`./gradlew :client:checkCourse -Pcourse=путь/к/course.json` (несколько файлов — через запятую): те же шаги, что у
импорта, без сохранения; печатает каждую ошибку с путём, код возврата 0 — файл импортируется.

Схема и код не расходятся: тесты (`SchemaTest` в `content`, `CourseSchemaTest` в `core`) проверяют, что
каждый образец и каждый файл, который пишет приложение, проходят схему; сломанные — не проходят; у каждого объекта
схемы ровно те поля, что у его класса; каждый тип упражнения, блока, рамки и правила есть в схеме.

### Версия формата

`"formatVersion"` — обязательное целое число в корне курса. Отвечает на вопрос:
**должно ли приложение знать всё, что есть в этом файле?**

| Файл | Что делает приложение |
|---|---|
| версия ≤ знакомой | строгий режим: незнакомое поле или тип — ошибка, это опечатка автора |
| версия > знакомой | мягкий режим: импорт с советом «Курс сделан в более новой версии Polylingy, обновите приложение» |
| версии нет | ошибка |

В мягком режиме незнакомое поле игнорируется, незнакомый блок — заглушка «доступно в новой версии»,
незнакомый тип упражнения не выдаётся (топик без знакомых упражнений помечается «нужна новая версия»).
Такой курс можно изучать, но **нельзя редактировать и экспортировать** до обновления — иначе при сохранении
потеряется то, чего приложение не понимает.

**Когда повышать:** когда в JSON становится можно написать то, чего предыдущая версия не знала.

| Изменение | Повышать? |
|---|---|
| новое поле, даже необязательное; новый тип упражнения или блока; новое значение перечисления | да |
| поле стало принимать больше (строка → строка или картинка) | да |
| ломающее изменение (избегаем) | да, плюс миграция |
| отрисовка, чекер, `TextMatcher`, политики, тексты ошибок, исправления импорта | нет |

Не чаще одного раза за мерж в `master`, как и версия приложения. Номер не зависит от версии приложения.
Повышение: поменять константу, дописать историю ниже, добавить файл-образец с новым полем.

Правила изменения формата, чтобы обходиться без ломающих изменений:
1. Новые поля — необязательные, со значением по умолчанию.
2. Поля не переименовываем и не удаляем; новое имя — синоним (`@JsonNames`), старое продолжаем принимать.
3. Смысл поля не меняем: другое поведение — новое поле или новый тип.

Миграции (функции «JSON версии n → JSON версии n+1») пишем, только когда понадобится ломающее изменение.
Первая — 1 → 2 (`CourseJson.upgrade`); 2 → 3, 3 → 4, 4 → 5, 5 → 6 и 6 → 7 меняют только номер. `examples/english-grammar.zip` нарочно остаётся в версии 1.
Схема описывает только текущую версию: при повышении в ней меняется `formatVersion.const` и добавляется новое.

## 10. Тесты

**Файлы-образцы (fixtures)** — курсы в JSON и zip в `client/src/desktopTest/resources/courses/`:
по образцу на каждый тип упражнения и блок, реалистичный юнит с картинками, курс в архиве.
**Добавленный образец никогда не правится, только добавляются новые** — так проверяется,
что старые курсы по-прежнему открываются.

| Тест | Что проверяет |
|---|---|
| импорт каждого образца | без ошибок, ожидаемый результат |
| импорт → экспорт → импорт | равные объекты; экспорт пишет текущую `formatVersion` |
| незнакомое поле в файле своей версии | ошибка с путём |
| файл новее: незнакомые поле, блок, тип | импорт с предупреждением, заглушки, курс не редактируется |
| `validate()` каждого типа | таблица неверных примеров → ожидаемые ошибки |
| чекер каждого типа | таблица ответов → `CORRECT` / `TYPO` / `WRONG` |
| UI каждого типа и блока | скриншоты на образцах, до и после проверки |
| слои | рамка и картинка на каждом типе проверяются (`ValidationTest`); виды и узкое окно — `LayersUiTest` |
| схема | образцы и всё, что пишет приложение, проходят `course.schema.json`; поля схемы = поля классов (`SchemaTest`, `CourseSchemaTest`) |
| `checkCourse` | хороший файл, ошибки с путями, нет картинки, нет файла (`CheckCourseTest`) |

## 11. Открытые вопросы

- Сопоставление: пункт — каждая пара (предложение) или всё упражнение целиком.
- Нужны ли: аудио, свободный ответ с самооценкой, «распредели по группам». «Найди и исправь» — `fix` (версия 3).
- Другие рамки (`chat`, `note`, `letter`) — когда понадобятся курсу; каждая — новое значение `look.type`.
- Текст итога после проверки («Almost — one mistake») — подобрать формулировки.
